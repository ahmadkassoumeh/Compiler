# Compiler Web Analyzer - starter project

This is an educational Spring Boot + Thymeleaf + ANTLR 4.13.2 project for the 2026/2027 Compiler Design assignment.

## Included

- Maven / Spring Boot web application.
- Thymeleaf page with a language selector for HTML + Thymeleaf, CSS, and Java.
- HTML lexer with a tag-reading mode and a separate HTML parser grammar.
- Semantic checks for the project's supported HTML element subset and matching opening/closing tag names.
- Combined CSS grammar (`Css.g4`).
- Java lexer and parser grammars aimed at ordinary Java classes and common Spring MVC Controller code.
- Token list and ANTLR Parse Tree output for the selected language.
- Arabic notes in `docs/`.

## Open in NetBeans

1. Extract the ZIP.
2. Open NetBeans and choose **File > Open Project**.
3. Select the `CompilerWebAnalyzer` folder (the folder containing `pom.xml`).
4. Wait for Maven dependencies to load.
5. Choose **Clean and Build**.
6. Run the project with the Spring Boot Maven goal `spring-boot:run` or use the project's configured Run action.
7. Open `http://localhost:8080`.

The Maven ANTLR plugin generates Java lexer/parser classes from the `.g4` files during the build. Do not edit generated files under `target/`; edit the grammar files under `src/main/antlr4/` instead.

## Try HTML + Thymeleaf

```html
<div th:if="${showProduct}">
  <h1 th:text="${productName}">Product</h1>
  <img src="/images/product.png" alt="Product">
</div>
```

The analyzer currently checks a defined set of HTML element names and compares each paired element's opening and closing tag names. An element outside that set is reported as unsupported by this project; this is not a claim that every unknown element is invalid in all HTML environments.

## Try Java / Spring MVC

Choose **Java (Spring Boot subset)** and paste:

```java
package com.example.demo;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class ProductController {

    @GetMapping("/products")
    public String listProducts(Model model) {
        model.addAttribute("pageTitle", "Products");
        return "products/list";
    }
}
```

The Java grammar recognizes a useful subset of Java syntax commonly found in Spring MVC controllers: packages/imports, classes, annotations, fields, methods, parameters, basic statements, method calls, and return expressions. It is not a complete Java language grammar. In particular, advanced generics, lambdas, records, switch expressions, and many less-common constructs are outside the current subset and may need to be added as the project grows.

## Current architecture

- `src/main/java/.../controller/AnalyzerController.java`: receives the browser's form request.
- `src/main/java/.../service/AnalyzerService.java`: selects the lexer/parser and performs analysis.
- `src/main/java/.../model/`: carries token and analysis results to the page.
- `src/main/antlr4/`: source grammar files written by the project team.
- `src/main/resources/templates/index.html`: Thymeleaf view.
- `src/main/resources/static/css/style.css`: page styling.
- `target/generated-sources/antlr4/`: Java source generated by ANTLR during Maven build; do not edit manually.

## Important distinction

The selected language in the web form is sent to the Spring MVC controller as a request parameter. The controller passes it to `AnalyzerService`, which chooses the generated lexer/parser classes. Imports such as `com.example.compiler.parser.java.JavaLexer` refer to classes generated from this project's `JavaLexer.g4` and `JavaParser.g4`; they are not built-in Java parsers supplied by the JDK.

The next project stage is to build AST/Visitor/Symbol Table and then connect Spring Controller mappings, `Model.addAttribute(...)` values, and Thymeleaf template names. The current Java feature provides tokenization and syntax parsing as the foundation for that relationship analysis.
